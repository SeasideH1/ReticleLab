# 0.2.10 update

- **Open configuration folder:** Game Bar uses a fixed, declared desktop-helper command that opens only its own package LocalState directory. This executes before the GSI receiver lock and never starts a second receiver or regenerates a token. Request IDs, a separate command lock, bounded waiting and explicit results prevent silent failures and stale replies. A selectable path is always available. Explorer may open behind Game Bar; Win+G reveals the desktop. No foreground-stealing API is used.
- **Smooth mouse trail:** a bounded 128-point motion history preserves turns between the existing approximately 30 Hz state publications. Motion history coalesces into 8 ms bins, retaining exact cumulative displacement. Display interpolates real samples through a 40 ms buffer, replacing its provisional endpoint instead of accumulating redundant points. It never predicts movement or synthesizes input. Existing frame cap, fixed viewport, downscaling and idle recentering remain intact.
- **Damage display:** unknown damage hides the entire number/label area. A known zero still displays 0. GSI settings distinguish missing player state, absent damage and invalid values. Exact whole-valued JSON numbers such as `100.0` are supported without rounding fractional values. The inspected local game cfg already enables `player_state` and `player_match_stats`; the stored custom-mode snapshot had no usable damage. This release cannot force a game/server to emit an absent field and does not substitute score, health, other-player data or memory reads.
- **Default configuration:** factory defaults now use the requested current appearance snapshot: cyan 3/1/2 crosshair, 1.13 input scale, 0.05 trail sensitivity, existing timings, tile positions and visibility. Only typed appearance preferences are embedded. Tokens, personal paths and host window placement are excluded; existing saved preferences are not overwritten by the update.
- **Layout persistence:** opening a widget no longer forces a default size or re-centers the crosshair. Game Bar continues to own/restore outer window positions; this SDK exposes no arbitrary-position setter. Window sizes persist separately in package LocalSettings. Settings saves merge only edited fields (including per-tile fields), and overlay drag writes read/modify/write under the same lock, preventing a stale view from undoing saved positions or scale. Interrupted pointer capture also saves the final drag position.

## Apply the update

A complete `ReticleLab-0.2.10-windows-x64.zip` installer, sanitized source ZIP and commit-tools ZIP are also available in the 0.2.10 delivery bundle. For a new computer, extract the complete installer ZIP and run `Install-ReticleLab.cmd`; it includes the x64 dependency and public development certificate. The update-only instructions below apply to the separately supplied update ZIP.

Extract the complete update ZIP and run `Update-ReticleLab.cmd` in the account that already has Reticle Lab 0.2.7 or newer installed. Windows closes only this package's running widgets/helper while updating, and retains settings and the GSI token. No separate runtime/dependency installer, certificate-trust changes or source archive is included. This is an update bundle containing a signed MSIX, not a binary-delta patch; MSIX still contains the app runtime.

After updating, open the GSI page and click **检查伤害数据** while playing. If it reports that the game did not send `round_totaldmg`, there is no reliable damage value for the overlay to display through the current GSI-only design.

Native visual behavior in an actual match requires acceptance after installation. Automated packet, interpolation, IPC, package and update validation cannot certify every Windows/Game Bar configuration.
